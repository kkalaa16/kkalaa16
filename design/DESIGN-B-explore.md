# DESIGN.md — Direction B: The Technical Plate

**Reading this as:** solo-engineer portfolio for aerospace/propulsion/ML recruiters, where the differentiator is methodological rigor rather than software-startup polish. The identity is drawn from the audited corpus itself — real CFD meshes, combustion diagrams, drag-coefficient curves — captioned the way an actual engineering report captions its figures, not decorated with an unrelated visual trend.

## Color
- `#EDEEE9` — Documentation paper — page background (cool grey-green, deliberately not the cream/brass "premium artisan" family)
- `#F6F6F2` — Panel — card and plate backgrounds
- `#14171A` — Carbon ink — primary text, 16.1:1 contrast
- `#4B5057` — Ink, dimmed — secondary text, 7.1:1 contrast
- `#C13A1D` — Hazard red-orange — the single accent (rules, CTAs, one badge outline)

## Type
- Display: heavy-weight system grotesk, uppercase, tight tracking — reads like a drawing title block.
- Body: same grotesk family at regular weight, sentence case, ~60ch measure.
- Mono: figure captions, data labels, spec strings (`Fig. 01`, `+51.7% UPTHRUST`).
- No serif anywhere — this is a technical-report register, not an editorial one.

## Tagline (locked 2026-07-15)
**"I find trends in chaos: physics, math, and machine learning."** — the cover sheet's fixed headline, above a mono-set, uppercase "I am a ___ Engineer" rotator (Combustion / Propulsion / Systems / ML / CFD Engineer) using the same typing effect the live site already has.

## Project-plate structure (locked 2026-07-15)
Every figure plate follows the corpus's own real shape (trade study → decision → number): **(1)** the alternatives actually compared, **(2)** the method/rig, **(3)** the quantified decision, **(4)** a one-line honest scope note, set as a small mono block with an accent rule — a caption-register callout, not a caveat buried in prose. Real scope notes should be chosen per-project with Krtin's sign-off; some (e.g. the thesis CFD case's convergence caveat) are more sensitive than others.

## Layout signature
Every project card is a numbered figure plate (`Fig. 01`, `Fig. 02`…) with a real image from the corpus and a one-line caption underneath, framed by hairline rules; the cover sheet (intro gate) reads like a document header — doc ID strip, name, tagline, rotator, credential, instrument list, "Open the file" action; drafting-style registration-mark ticks appear only at the cover sheet's corners, never as page-wide decoration.

## Banned on this page
- The AI-default cream+brass+oxblood "premium artisan" palette family
- Decorative section numbering (figure numbers are only used on real captioned images)
- Serif type
- Any second theme — this is a deliberate single-substrate identity, like a printed report

## Single-theme rationale
A printed engineering report doesn't ship a dark-mode edition. Direction B commits to the light paper world on purpose; Direction A already covers the dark-mode-native reader.

## v6: potential flow around the cursor, with a shed wake
Same canvas architecture as v5 (full-bleed, `z-index:0`, color-on-disturbance, `prefers-reduced-motion` draws one static frame and skips the mousemove listener). What changed is the physics driving it, chosen specifically to read as fluid/aero rather than electrical:

- **Tracer particles**, not lines — ~90 points drift with a slow uniform ambient flow (left to right), reading as a wind-tunnel dye/smoke visualization rather than a waveform.
- **The cursor is a bluff-body obstacle.** Near-field deflection is the actual closed-form 2D potential-flow solution for uniform flow around a cylinder (`u = U(1 - R²(dx²-dy²)/r⁴)`, `v = U(-2R²dx·dy/r⁴)`, from superposing a uniform stream with a doublet) — real textbook aerodynamics, not an approximation. It correctly reproduces the classic result that flow speeds up to 2x freestream at the sides of the cylinder.
- **An alternating von Karman vortex street sheds downstream.** Every ~0.42s a new point vortex spawns just behind the cursor, alternating sign top/bottom. Each is a regularized (core-smoothed) point vortex — `mag = Γ / (2π(r²/core² + 1))` — the same smoothed discrete-vortex technique noted in the RI-NJ pump-acoustics corpus (`Inviscid discrete vortex method with artificial viscosity`). Vortices advect downstream with the ambient flow, decay in strength (`Γ *= 0.986`/frame), and are culled once weak or old enough — a real (simplified) wake-turbulence model, not a decorative swirl.
- **Color still marks disturbance only**: particle stroke color blends from muted ink toward the accent hazard-red based on proximity to the cylinder or to an active vortex (scaled by that vortex's remaining strength), never a blanket color wash.

**Visibility tuning pass (same day):** first build was "barely visible." Increased: obstacle radius 46→78px, particle count 90→170, vortex shedding interval 0.42s→0.26s, vortex initial strength 3200→4400, vortex core 22→30px, disturb-radius thresholds (190px cylinder / 130px vortex, up from 140/90), line width 1.1→1.6. Color: calm baseline moved from near-black ink to `--ink-dim` (#4B5057, the same neutral already used for secondary text elsewhere, so it's not a new hue) at higher base alpha (0.34 vs 0.16); disturbed state moved from the flat page accent to a brighter, more saturated red (`rgb(232,58,24)`) specifically for this field, since the flat accent was blending into the paper at low alpha.

**Rendering model swap, attempt 1 (v7, superseded same day):** the 170-particle cloud was replaced with `LINES = 16` continuous curves, each *re-traced from scratch every frame* from a fixed left-edge seed through the current velocity field (a proper instantaneous streamline plot, the ParaView/Tecplot technique). **Feedback: "it doesnt do vortex shedding it sends off the lines in an awkward sort of glitchy animation."** Root cause: full re-solving a ~300-step path through a field that itself changes every frame (vortices constantly spawning/moving/decaying) amplifies tiny frame-to-frame differences into large changes in the resulting path, especially near vortex cores where the flow is genuinely most sensitive — an Eulerian full-field-resolve is the wrong technique for smooth *temporal* animation of a rapidly-evolving field, even though it's correct for a single static snapshot.

**Rendering model, attempt 2 (v8, superseded same day):** switched to a Lagrangian streakline approach — the actual wind-tunnel dye/smoke visualization technique. `CARRIERS = 18` points advected smoothly frame-to-frame with a `TRAIL = 90`-point trailing history drawn as one connected curve (gradient-colored tail-to-head, one `stroke()` call). Added a velocity speed cap (`mag > 70`) so a carrier near a strong vortex core curls instead of teleporting past it. **Feedback: "the physics of vortex shedding is wrong... dont just send streaklines in batches, they should be continuously happening."** Two separate real bugs found:

1. **Vortex/flow speed mismatch.** Vortices advected via `vt.x += U * dt * 0.9` while everything else in the field (carriers) advected via `* dt * 0.28` — vortices were moving roughly 3x faster than the flow field they're supposed to be embedded in, decoupling the wake from the streaklines meant to curl through it.
2. **Wrong row-spacing ratio.** Vortices spawned at `mouseY ± R*0.85` (~66px half-offset, tied to the 78px obstacle radius) with no relation to the actual von Karman stability criterion, giving h/l (row separation / streamwise spacing) ~1.18 — a real von Karman street's stable ratio is h/l ~0.281. The rows were far too widely separated relative to their spacing to read as a real staggered street.
3. **Carriers batching.** All 18 carriers seeded near the same starting position/time tended to cross and re-enter the canvas in visible synchronized waves rather than a continuous stream.

**v9 (current) fixes:**
- Vortex advection now uses the same `dt*0.28` scale as the rest of the field, matched with a `U*0.9` base convection speed (real von Karman streets convect slightly under freestream) plus **real mutual induction** — each vortex now also gets pushed by the velocity induced by every *other* active vortex (`vortexVel(vt.x, vt.y, excludeSelf)`), which is the actual physical mechanism that makes a von Karman street self-sustaining, not just two independently-drifting rows.
- Row half-offset reduced to a fixed 22px (44px row separation) and shedding interval retimed to 0.3s, chosen together to land close to the real h/l ~0.281 ratio given the corrected convection speed.
- Carriers (`CARRIERS = 24`) now spawn/respawn at staggered depths behind the left edge (`-20 - Math.random()*280`, not a fixed x) and each carries a personal `speedMult` (0.8-1.2x) so they naturally desynchronize over time instead of arriving in batches.

## v11 (current): rotating vortex-core glyphs added
**Feedback:** user pointed to a reference video of real Karman vortex shedding and said the rendering was "nowhere close." The reference video could not be fetched in this environment (yt-dlp timed out repeatedly reaching Google's video CDN, a network restriction of this sandbox, confirmed after 20 retries) — diagnosis below is from fluid-dynamics/flow-visualization fundamentals, not a frame-by-frame comparison.

**Root cause:** v10's channels are a height-map, `y = f(x)` — one value per x-position. That representation can wave, but it can never spin, because a function's graph cannot loop back on itself. The one unmistakable visual signature of a real von Karman street, in every wind-tunnel dye/smoke video, is **visibly rotating cores** — alternating spinning eddies, not an undulating line. No amount of tuning wave amplitude/frequency on a height-map can produce that, regardless of how correct the underlying vortex position/strength/decay physics is (which was already fixed in v9).

**Fix:** kept the v10 continuous channel lines (still needed for the general ambient flow and to avoid the earlier "discrete trains" problem), and added an explicit rotating spiral glyph drawn directly at each active vortex's real position — a parametric spiral (`turns=1.35`, 22 segments) rotating at `t*3.4*sign` (so direction of spin matches the vortex's own sign), radius scaled by `sqrt(strength/4400)` (bigger when fresh, shrinking as it decays), stroked in the accent color at high visibility regardless of ambient disturbance level. This is drawn as a separate layer on top of the channel lines each frame, using the same `vortices` array v9 already tracks (no change to the underlying shedding/advection/mutual-induction physics, only to what's visualized).

## v12 (current): clean occlusion at the body, disturbance confined to the wake
**Feedback:** "the flow should be disrupted behind the cursor not have lines oscillating where the lines are in contact with the cursor... think of it like streamlines" — real streamlines never touch a solid body, they part cleanly around it. The jitter at contact was the pure potential-flow term itself: cylinder deflection is most sensitive right at `r~R` (velocity peaks at 2x freestream at the cylinder's sides), so as a live cursor moves, samples near it were chasing a rapidly-changing target every frame, reading as noise exactly where the "obstacle" was.

**Fix:** each channel now checks, per sample, whether `(x, baseY)` falls inside the obstacle's radius (`dcx^2+dcy^2 < R^2`). Inside it, nothing is drawn (a real gap, `needMove` flag forces the next visible point to `moveTo` rather than `lineTo`) instead of showing the raw near-field deflection. The line still computes and eases its target position every sample (so it re-emerges at the correct height on the far side), it just isn't drawn while inside the body. Wake vortices (already correctly modeled, unchanged) continue to shape the surrounding lines exactly as before — the visible effect is now cleanly localized to the wake instead of blurred together with contact-point jitter.

## v13 (current): shared velocity grid + real parametric streamlines
**Feedback:** "the flow should be disrupted behind the cursor... the entire flow field should be disrupted and not just the respective streamline... streamlines should bend around the cursor and lead the vortices... think of it like streamlines." Confirmed via a plan-mode diagnosis session (2026-07-19) that v12's per-channel height-map (`y=f(x)`, evaluated independently per row) had three structural limits: (1) a function's graph can't move in x, so it can't really "bend around" an obstacle, only wobble vertically at a fixed column; (2) each channel only samples the field at its own fixed row, so there's no coupling between neighbors, meaning only 1-2 rows near a vortex visibly react; (3) vortex/color falloff radii were narrow relative to channel spacing, so the effective reach was small.

**Rebuild (chosen over 3 easier alternatives after user review):**
1. **Shared velocity grid** (`GRID_COLS x GRID_ROWS` = 64x36) — `cylinderVel`+`vortexVel`+ambient evaluated once per coarse cell each frame, not independently at scattered points. `sampleGridVel()` bilinearly interpolates. Every consumer (streamline points, `disturbAt` for color) reads this one field, so shape and color always agree and disruption is naturally graded across neighboring lines instead of isolated spikes.
2. **Real (x,y) "rope" streamlines**, replacing the height-map entirely. Each of `LINES=16` lines is a chain of points with a fixed rest anchor (`rx,ry`, evenly spaced -- guarantees full-width coverage) plus a mutable `(dx,dy)` offset. Each frame, the offset eases (`EASE=0.1`) toward the local DISTURBANCE velocity (grid velocity minus ambient `U`) sampled at the point's own current (already-displaced) position, scaled by `DISP_K=3` and clamped to `MAX_DISP=110px` (prevents runaway near a strong vortex core). This lets a point genuinely bow in both x and y near the obstacle, hug the boundary, and carry that same bowed shape smoothly into the wake as one continuous curve -- offset relaxes back toward 0 automatically far from any disturbance, since disturbance velocity itself is ~0 there. No full re-solve from a seed (that was the v7 jitter bug) -- each point only ever eases toward a target derived from its own last state.
3. **Guaranteed no-invasion backstop**: a hard radial push keeps any point from ever rendering inside the obstacle radius (`R+2`), on top of (not instead of) the physics already pushing flow around it -- replaces v12's hard occlusion gap, so the line stays visually continuous (hugs the boundary) instead of vanishing and reappearing.
4. Rotating vortex-core glyphs (v11) kept unchanged, drawn on top.

Also fixed: removed the now-unused `localVy` helper (replaced by grid sampling); performance improved (the grid consolidates what used to be ~3200 independent full-physics evaluations per frame into ~2300 grid-cell evaluations, with all streamline points then doing cheap bilinear lookups instead).

## v14 (superseded): extended wake reach, fixed solid-ring artifact
**Feedback (with screenshot):** the wake wasn't extending downstream at all -- disruption looked confined to a tight cluster right at the cursor, with a visually dominant, unnaturally solid-looking circle traced right around it. "Why is the shedding not happening in the wake of the cursor? it is only limited to the cursor. Correct physics would ensure it'd go back."

**Two real, separate bugs found:**
1. **Vortex lifetime/decay far too aggressive for the visual to read as an extended wake.** `strength *= 0.988`/frame with a hard `age > 5.2s` cutoff gives roughly a 1-second half-life -- a vortex was losing most of its strength (and being fully culled) well before it traveled far enough downstream to be visually distinct from a cluster near the cursor. Real wakes persist for many body-widths. Fixed: decay slowed to `0.994`/frame, lifetime extended to `11s` (roughly doubling both the persistence time and the downstream travel distance before a vortex fades out).
2. **The no-invasion backstop was creating a visually solid ring.** Since the backstop pushes any point within `R+2` of the cursor out to exactly `r=R+2`, and a single line can have many consecutive points all inside that radius as it passes near the cursor, they all landed on the exact same circle -- reading as one thick, unnaturally perfect ring rather than a natural boundary. Fixed: gave each point a small, stable (assigned once at line creation, not re-randomized per frame -- avoids flicker) `jitter` value added to its personal push-out radius, so nearby points settle on slightly different radii and the boundary reads as a soft edge instead of a solid ring.

## v15 (current, streamline branch): eased-target boundary, fixes hard snap
**Feedback (with screenshot):** a sharp near-vertical spike appeared in a line right where it crossed the obstacle boundary. "The decaying is still not smooth."

**Root cause:** the no-invasion backstop (v14's jitter fix) was writing directly into the eased state -- `p.dx = fx - p.rx; p.dy = fy - p.ry;` -- the instant a point's rendered position crossed into the obstacle radius. That's a hard overwrite that completely bypasses `EASE`, so the point's position jumped in a single frame instead of approaching the boundary smoothly like everything else in the field.

**Fix:** redirect the easing TARGET (`tdx,tdy`) toward the boundary before the `p.dx += (tdx-p.dx)*EASE` step, so the approach itself is eased like any other target change. The final render-time clamp (`fx,fy`) is now a pure visual safety net that never writes back into `p.dx`/`p.dy`, so it can't reintroduce a state discontinuity into the next frame. Applied identically in the Hybrid mockup. General lesson for this codebase: any hard constraint/backstop on eased motion must redirect the target, never overwrite the eased state directly.

## v16 (current, new branch): Fluid Bloom -- ink bleeding into paper
**Request:** "create a version of B where instead of bending streamlines we have a fluid bloom like i had at the opening of my original website." Not a bug fix on the vortex-street engine -- a deliberately different mechanic to compare against it, reviving the spirit of the original site's mouse-reactive WebGL fluid intro but reframed for this identity.

**Mechanic:** two layers, no vector field, no vortex bookkeeping. (1) A persistent, very faint stain accumulates on an offscreen canvas as the cursor moves -- the page remembers where you've been, like a well-used notebook, never fully clearing. (2) Live blooms (`ctx.createRadialGradient`) expand and fade over ~1-1.5s, spawned on `mousemove` throttled to roughly every 22px of movement so they don't spawn every frame. Two slow ambient "wells" auto-splat every ~2.2s (echoing the original site's actual `initFluid()` auto-splat behavior) so the canvas has idle life without interaction. Color restricted to the single locked accent (`#C13A1D`) family, alpha-only variation -- no new hues, per the durable "color directs attention, doesn't fill the page" rule. `prefers-reduced-motion` renders two fixed static stains, no listeners, no animation loop.

**Relationship to the streamline branch:** kept as a separate file (`direction-b-fluidbloom-mockup.html`), not a replacement -- both are live comparisons of the same cover-sheet/hero/card/skills/patents content with two different motion identities for the mouse-reactive field. Everything outside the field engine (copy, layout, cat animation, tokens) is identical to v15.

## v17 (current, fluid-bloom branch): matched the real fluid-intro recipe, dropped mouse reactivity
**Feedback:** "the fluid bloom is not as well as it should be... quite intense where the fluid shimmers and flows. But it didnt interact with the mouse." v16 built the bloom mechanic backwards -- it was mostly mouse-throttled spawns with a faint, infrequent ambient pass, when the real original (`app.js` `initFluid()`, read directly from the pristine reference clone) is the reverse: two auto-splatting "wells" on slow independent orbits, stamped into the sim continuously (every 3 frames), a 5-splat burst on load, and an occasional wide random splat -- no cursor involvement anywhere.

**Fix:** removed all `mousemove`/`mouseleave` listeners and cursor-throttled spawning entirely. Two wells now drift on slow wobbling orbits (`wob` phase drift added on top of the base velocity so paths aren't perfect circles) and, every frame, each draws three offset, independently-phased radial-gradient layers with pulsing radii (a single static gradient reads flat; layering several gives the shimmering, textured edge the original's turbulent WebGL sim had) plus stamps continuously into the persistent low-dissipation stain layer (`0.006` fade/frame, close to the original's `DENSITY_DISSIPATION .997`). A 6-splat burst fires on load and a wide random splat fires every ~3.5s, both matching the original's actual constants.

## v10 (superseded): continuous full-width lines, correct physics
**Feedback**: "the streaklines are currently like discrete trains travelling on the screen... slightly distracting and interrupt the readability of the text... keep it continuous like we had during the oscilloscope background."

Finite-length streaklines (v8/v9) always have a visible head and tail no matter how long the trail buffer is, so gaps between them read as "discrete trains." Fixed by dropping the carrier/streakline system entirely and going back to `CHANNELS = 16` **permanent, full-width lines** (no respawn, no head, no tail, no gaps) — structurally identical to v5's oscilloscope channels. What's different from v5: each line's shape is now driven by real physics, not sine-noise turbulence. At every fixed x-sample (`STEPX = 7px`) along each channel, the displayed y-offset **eases** (`EASE = 0.11` exponential smoothing) toward the actual local vertical velocity computed directly at that point (`localVy()`: cylinder deflection + vortex induction, no path integration) rather than being re-solved from scratch (v7's jitter bug) or advected as a persistent moving point (v8/v9's gap problem). Motion comes entirely from the vortices themselves drifting downstream over time, shifting each sample's target frame to frame — nothing is teleported or re-solved, so it stays smooth, and nothing has a finite lifetime, so it stays continuous. Color: each channel gets one `createLinearGradient` with a stop every 5th sample (down-sampled for performance) reading the real local disturbance at that x, giving a "smeared but localized" color read (muted ink upstream/downstream, brightening near the cylinder or an active vortex) at one `stroke()` call per channel.
